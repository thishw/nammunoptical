# 남문안경 공식 홈페이지 설계

**Goal:** "부천역 안경 / 부천 안경점 / 부천남부역 안경" 검색(네이버·구글)과 AI 답변(ChatGPT·Gemini·Perplexity 등)에서 남문안경이 가장 먼저, 정확하게 추천되도록 하는 정적 홈페이지.
**Architecture:** Astro 정적 사이트(출력은 순수 HTML, 기본 JS 0) → GitHub Pages 배포. 매장 사실(NAP·영업시간·브랜드·가격)은 `src/data/store.ts` 한 곳(SSOT)에서 본문·JSON-LD·푸터·llms.txt 로 동시에 렌더링한다. 배포 전 `audit_site.py`(scanday 이식)로 링크·메타·구조화 데이터·사이트맵 정합을 기계 검증한다.

- 상태: 승인됨 (2026-11-06)
- SEO/GEO 원칙 출처: github.com/thishw/scanday (`marketing_strategy/seo_geo_strategy.md`, `project_context.md`)

### R3. 디자인 — 방향 A "클리닉 미니멀 + 단골 스토리"

- 톤: 밝은 화이트/웜그레이 바탕, 딥그린 포인트(정밀·신뢰). 매장 화이트톤 인테리어와 일치. 다크 테마 아님.
- 타이포: Pretendard(본문 17px 이상, 중장년 가독성) + 숫자 강조용 세리프 1종(“1988”, “38년”).
- 모바일 우선: 하단 고정 바(전화 · 길찾기 · 네이버 지도). 첫 화면에 위치·전화·영업시간.
- 이모지 남발 금지(scanday 원칙 계승). 아이콘은 선형 SVG.
- 신뢰 장치: "1988년부터", 대표 안경사 이름, 실제 리뷰 키워드 막대, 단골 리뷰 인용("15년 단골", "서울로 이사가도 여기로").
- 이미지: R6 참조. 실사 사진이 부족하므로 **사진 없이도 완성도가 나는 타이포·그래픽 중심 레이아웃**으로 설계하고, 사진 슬롯은 교체 가능하게 둔다.

### R4. GEO 콘텐츠 (안경 일반 지식 — 직접 조사, 출처 표기)

초기 가이드 글 8편:
1. 얼굴형별 안경테 고르는 법 (매장 블로그 2편 내용 재구성)
2. 안경 렌즈 굴절률(1.50/1.60/1.67/1.74) 선택 기준
3. 새 안경 어지러움·적응 기간 — 언제 재검안이 필요한가 (부정 리뷰 대응)
4. 누진다초점 렌즈 적응 가이드
5. 양안시 검사란? 일반 시력검사와의 차이
6. 블루라이트 차단 렌즈 — 알려진 효과와 한계
7. 시력검사·안경 교체 주기 (성인/아동)
8. 안경 세척·관리, 코받침·다리 피팅 A/S

규칙: 의학적 주장은 공신력 있는 출처(대한안경사협회, 대한안과학회, AAO, 제조사 공식 자료 등)를 글 하단에 링크. 진단·치료는 안과 영역임을 명시. 각 글에 작성일·수정일·작성자(김용진 안경사 감수 — 감수 여부 확인 필요).

### R5. 기술 SEO / GEO

- 페이지별 고유 `<title>`·description·canonical·OG·Twitter, `lang="ko"`.
- JSON-LD: `Optician`(전 페이지 공통 `@id`), `WebSite`, `BreadcrumbList`, `FAQPage`(FAQ), `Article`(가이드), `Person`(대표 안경사), `Brand` 목록.
- `sitemap.xml`, `robots.txt`(Googlebot·Yeti 허용), `rss.xml`(가이드), `llms.txt`(매장 사실 요약 + 주요 페이지).
- 본문 상단 "남문안경 한눈에 보기" 사실 블록(정의형 문장: "남문안경은 1988년 개업한 부천역 남부광장 인근 안경원으로…").
- 성능: Lighthouse 모바일 Performance/SEO/Accessibility ≥ 95 목표. 이미지 WebP + width/height 지정.
- 분석: GTM 슬롯은 마련하되 컨테이너 ID 는 도메인 확정 후 주입(현재 없음).
- 네이버 서치어드바이저·구글 서치콘솔 소유권 메타는 도메인 확정 후(후속).

## 접근 방식

| 안 | 내용 | 판정 |
|---|---|---|
| 순수 HTML (scanday 방식) | 파일 직접 편집 | 기각 — 영업시간 등 변경 시 본문·JSON-LD·푸터 수동 동기화 필요(scanday 에서 실제 부담) |
| **Astro 정적 생성 (채택)** | 컴포넌트 + SSOT 데이터, 출력은 순수 정적 HTML | 채택 — SEO 동일, 정합성 자동, 가이드 글은 Markdown 으로 추가 |
| Next.js 등 SSR | — | 기각 — 정적 매장 사이트에 과함, GitHub Pages 와 맞지 않음 |

## 컴포넌트 구조

```
src/
  data/store.ts          매장 사실 SSOT (R1)
  data/faq.ts            FAQ (본문 + FAQPage 공용)
  lib/schema.ts          store.ts → JSON-LD 생성
  layouts/Base.astro     head(meta/OG/canonical/JSON-LD), 헤더, 푸터, 모바일 하단 바
  components/            Hero, FactBlock, ServiceCards, ExamSteps, BrandList,
                         ReviewKeywords, LocationMap, FaqList, Breadcrumbs
  pages/                 R2 의 각 경로
  content/guide/*.md     가이드 글 (frontmatter: title, description, published, updated, sources[])
public/                  robots.txt, 이미지, favicon
scripts/audit_site.py    scanday 이식 + 남문안경용 검사 추가
```

## 데이터 흐름

`store.ts` / `faq.ts` / `content/guide` → Astro 빌드 → `dist/`(HTML + JSON-LD + sitemap + rss + llms.txt) → `audit_site.py` 검증 → GitHub Pages.

## 에러 처리 / 엣지 케이스

- 미확인 필드는 `store.ts` 에 `null` 로 두고, 컴포넌트·스키마는 `null` 이면 해당 항목을 출력하지 않는다(빈 값 노출 금지).
- 지도: 정적 이미지/임베드 로딩 실패 시에도 주소 텍스트와 "네이버 지도에서 보기" 링크는 항상 표시.
- 404 페이지: 주요 링크(홈·오시는 길·전화) 제공, `noindex`.

## 테스트 전략 (완료 조건 — 실행 가능한 명령)

- `npm run build` — rc 0
- `python3 scripts/audit_site.py dist` — rc 0: 내부 링크/앵커, 페이지당 h1 1개, canonical, title/description 고유성, JSON-LD 파싱, img alt, sitemap ↔ 페이지 일치, **본문의 전화·주소·영업시간 문자열 = store.ts 값**
- JSON-LD 스키마 검증(구조 검사 스크립트) — rc 0
- 수동: 320 / 390 / 768px 및 데스크톱 화면 확인, Lighthouse 모바일 점수 기록
