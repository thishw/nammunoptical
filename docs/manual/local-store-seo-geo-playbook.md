# 동네 매장 홈페이지 SEO·GEO 구축 매뉴얼

남문안경(https://nammunoptical.com)을 만들며 실제로 거친 과정을 다음 매장에 그대로 재현할 수 있게 정리한 문서다.
목표는 "<지역> <업종>" 검색(네이버·구글·다음)과 AI 답변(ChatGPT·Perplexity·Gemini 등)에서 매장이 **정확한 정보로 먼저 추천**되는 것.

- 근거 기록: Claude Code 세션(2026-11-06 ~ 11-09, 설계·구현·1·2차 리뷰) + Hermes 세션(2026-11-23 ~ 11-24, 운영자 확인·공개·검색엔진 등록·3차 리뷰)
- 실제 산출물: 이 저장소 전체. 스펙 `docs/specs/2026-11-06-namun-optical-site.md`, 계획·검증 기록 `docs/plans/2026-11-06-namun-optical-site/plan.md`, 결함 기록 `docs/works/feedback/ledger.md`
- 에이전트용 절차: Hermes 스킬 `local-business-website` (이 매뉴얼과 같은 내용을 에이전트 실행 단위로 나눔)

## 0. 한눈에 보기

| 단계 | 하는 일 | 사람이 할 일 | 남문안경 소요 |
|---|---|---|---|
| 1. 착수·조사 | 네이버 플레이스·참고 레포 분석, 디자인 방향 3안 | 방향 고르기 | 15분 |

| 4. 구현 | Astro 정적 사이트, 매장 사실 SSOT, 가이드 글 8편(병렬) | – | 30분 |

원칙 세 가지가 전 단계를 관통한다.

1. **확인된 사실만 쓴다.** 운영자나 네이버 플레이스로 확인 안 된 값은 화면·구조화 데이터·llms.txt 어디에도 내보내지 않는다(비워 두거나 "전화 확인").
2. **매장 사실은 한 파일에만 쓴다.** `src/data/store.ts` 하나를 고치면 본문·JSON-LD·푸터·llms.txt·가이드 매장 안내가 함께 바뀐다.
3. **검사는 스크립트로 강제한다.** 사람이 실수한 패턴은 감사 스크립트 규칙으로 만들고, 일부러 위반을 넣어 실패하는지(음성 테스트)까지 확인한다.

## 1. 착수·조사

입력: 매장 네이버 플레이스 URL, 참고할 SEO/GEO 레포(남문안경은 `thishw/scanday`), "부족한 정보는 물어보고 일반 지식은 직접 조사" 지시.

1. 네이버 플레이스 데이터 확보
   - `map.naver.com` 은 직접 읽히지 않는다. `pcmap.place.naver.com/place/<id>/home` 을 브라우저로 열고 `window.__APOLLO_STATE__` 의 `PlaceDetailBase:<id>` 를 읽는다.
   - 얻는 값: 도로명·지번 주소, 좌표, 전화, 리뷰 수·평점, 리뷰 키워드, 결제수단, 비어 있는 항목(`missingInfo` — 영업시간·소개글·편의시설 미등록 여부).
   - 리뷰 본문에서 "15년 단골", "가족 모두 여기서" 같은 **실제 신뢰 문구**와 부정 리뷰(예: "새 안경이 어지러웠다")를 뽑는다. 부정 리뷰는 가이드 글 주제가 된다.
2. 참고 레포에서 가져올 것: LocalBusiness 계열 JSON-LD, sitemap·RSS, 감사 스크립트, "본문 = 구조화 데이터" 원칙, 숨김 키워드·최상급 금지.
3. 디자인 방향 3안을 표로 제시하고 추천안 1개를 고른다(장점·약점·타깃 연령).
   - 남문안경: "클리닉 미니멀(화이트·웜그레이·딥그린) + 단골 스토리". 근거 = 실제 화이트톤 매장, 50~60대 누진 고객 가독성, AI가 정보를 뽑기 쉬운 구조.
   - 모바일 우선: 본문 17px 이상, 하단 고정 바(전화·길찾기·지도), 첫 화면에 위치·전화·영업시간.

## 2. 정보 수집 (질문지)

한 번에 묻고, 사용자는 번호로 짧게 답한다("맞음", "대기", "너가 찾아"). 답 하나하나를 `store.ts` 필드에 매핑한다.

**1차 질문지 (착수 때)**
1. 영업시간, 휴무 요일, 공휴일 운영
2. 개업 연도, 대표자 이름·경력, 처음부터 같은 자리인지, 창업자인지
3. 검사·장비·핵심 서비스 (안경원: 자동굴절검사기, 양안시 검사, 누진다초점, 아동 근시관리 렌즈)
4. 대표 브랜드 (그 외에도 다수 취급인지 — 거의 항상 "예")
5. 가격 공개 범위, "OO원부터"의 기준 품목
6. 주차
7. 매장 사진·블로그·스마트스토어
8. 도메인 구매 여부, 네이버 스마트플레이스 관리 권한

**2차 질문지 (구현 후, FAQ·GEO 가치가 큰 것)**
- 우편번호(직접 조회 가능), 주차 상세, 결제수단(카드·현금영수증·지역화폐·제로페이), 다른 취급 브랜드, 검사 소요 시간, A/S 정책, 대표 경력·직원 구성, 선글라스·콘택트렌즈 브랜드
- 남문안경 답 예: 검사 10~15분, "구입 후 1년 이내 무상, 피팅·코받침 평생 무료", "대표 40년 이상 경력, 젊은 감각의 직원들"

**규칙**
- 운영자가 마케팅 단순화를 원하면 따르되 거짓이 되지 않게 쓴다. 예: 1만원 기준이 테만이면 "안경 10,000원부터"가 아니라 "10,000원부터"로, 실제 기준은 코드 주석에 남긴다.
- 브랜드는 항상 "대표 브랜드 … 등/다수". 목록이 전부인 것처럼 쓰지 않는다(운영자가 가장 먼저 지적한 부분).
- 답은 스펙 문서 끝 "운영자 확인 (날짜)" 표에 기록하고 `store.ts` 에 `// 운영자 확인 YYYY-MM-DD` 주석을 단다.
- 주소 원천 = 운영자 + 네이버 플레이스. 도로명주소 조회 사이트는 우편번호에만 쓰고, 그쪽 지번(대표 필지라 다를 수 있음)은 채택하지 않는다.

## 3. 설계·계획 (문서)

- 스펙 `docs/specs/<날짜>-<slug>.md`: R1 매장 사실표(값·출처) + 출력 규칙, R2 페이지 구성(경로별 타깃 검색어), R3 디자인, R4 GEO 콘텐츠 목록, R5 기술 SEO/GEO, R6 이미지, 미결 질문.

- 결함 기록 `docs/works/feedback/ledger.md`: 리뷰에서 나온 결함 패턴을 빈도·최근일과 함께 쌓는다(F-001 미확인 사실 단정, F-002 SSOT 밖 리터럴, F-003 FAQPage 중복 …).

## 4. 구현 (사이트 청사진)

**스택**: Astro 정적 생성(출력은 순수 HTML) + GitHub Pages. 의존성은 2주 이상 지난 버전으로 정확히 고정. 폰트는 자체 호스팅(외부 CDN 없음).

**구조**
```
src/data/store.ts      매장 사실 SSOT + 파생 문구 헬퍼(walkText, priceText, aftercareText, phoneEuro …)
src/data/services.ts   서비스 페이지 본문·FAQ (QA.schema=false 면 FAQPage 마크업 제외)
src/data/faq.ts        매장 공통 FAQ
src/data/photos.ts     매장 사진 목록(key·alt·캡션·촬영연도·그룹)
src/data/site.ts       GTM ID, 검색엔진 소유확인 코드, 메뉴
src/lib/schema.ts      JSON-LD: Optician(LocalBusiness 계열)·WebSite·Person·BreadcrumbList·FAQPage·Article
src/content/guide/*.md 정보형 가이드 글 (zod 스키마: title≤60, description 40–200, summary, faq[], sources[≥1])
src/pages/             홈·소개·서비스 N종·브랜드·오시는 길·FAQ·가이드·매장 사진·404 + llms.txt / robots.txt / rss.xml 엔드포인트
scripts/audit_site.py  배포 게이트(아래)
scripts/check_overflow.py  390px 가로 넘침 검사(headless Chrome)
```

**페이지 구성(IA)과 타깃 검색어**
- `/` "부천역 안경, 부천 안경점": 히어로("1988년부터 같은 자리"), 한눈에 보기 사실 블록, 찾는 이유 3카드, 검사 과정, 서비스, 리뷰 키워드 막대, 가이드, 오시는 길, FAQ
- `/services/<slug>/` 서비스별(시력검사·누진다초점·어린이·콘택트렌즈·선글라스): 본문 섹션 + 서비스 FAQ + 관련 가이드
- `/brands/` "부천 카잘" 등 브랜드 검색어: 대표 브랜드 + "다수" 카드, 상표 고지
- `/location/` 도보 경로·버스·주차, 지도(클릭 시 네이버 지도), 외관 사진
- `/guide/` 정보형 롱테일(AI 인용 대상)
- `/faq/`, `/about/`(개업 스토리·대표), `/gallery/`(매장 사진)

**SEO**
- 페이지마다 고유 title·description, canonical(절대경로·끝 슬래시), OG·Twitter, `lang="ko"`, h1 1개, img alt·width·height.
- JSON-LD는 화면에 보이는 값과 같아야 한다. 영업시간 `openingHoursSpecification` 은 요일이 확정된 뒤에만 출력.
- `AggregateRating`·Review 마크업 금지(자기 게재 리뷰). 리뷰 수치는 "네이버 플레이스 기준, 날짜"와 함께 본문에만.
- 같은 질문(의미가 같은 다른 문구 포함)을 여러 페이지에 FAQPage로 넣지 않는다.

**GEO (AI 답변 엔진 대응)**
- 홈 상단 정의형 문장: "남문안경은 1988년 개업한 부천역 남부광장 인근 안경원으로 …" — AI가 그대로 인용할 수 있는 문장.
- `llms.txt`: 매장 사실 요약(주소·우편번호·좌표·전화·영업시간·가격·A/S·결제·브랜드 등) + 주요 페이지·가이드 목록. `store.ts` 에서 생성.
- 가이드 글: 섹션 첫 문장 = 질문에 대한 직답, 표·번호 목록, 글별 FAQ 2~4개, **실제로 열어 확인한 공신력 있는 출처 2개 이상**(제조사·AAO·NHS·Cochrane·질병관리청 등), 의학적 진단은 전문의 영역 명시, 작성일·수정일, 바이라인은 매장 이름(개인 감수 표기는 운영자 허락 시에만).
- 가이드 마크다운에는 주제 문장만 쓰고, 끝의 매장 안내(주소·도보·주차·영업시간·전화)는 템플릿이 `store.ts` 로 그린다.
- 부정 리뷰 주제는 정직한 정보 글로 답한다(남문안경: "새 안경 어지러움 원인과 적응 기간, 재검안 시점").

**문구 규칙**
- 최상급 금지(최고·1위·No.1·완벽), 숨김 키워드 금지. 신뢰는 검증 가능한 사실("1988년 개업", "같은 자리 38년")로.
- 한국어 조사: 생성된 목록 끝이 "등"이면 "등을/등의"만. 전화번호 뒤 조사는 마지막 숫자 읽기 기준(…9540 → "으로"), 헬퍼 하나(`phoneEuro`)로만 출력.
- 새 창 링크는 `rel="noopener noreferrer"` + 화면낭독기용 "(새 창)".

## 5. 검증

**감사 스크립트 `audit_site.py` (배포 게이트, 실패하면 배포 안 됨)**
- 페이지: lang, h1=1, title·description 존재·고유, canonical 1개·일치, og:image, noindex 페이지 canonical 금지
- JSON-LD: 파싱, 매장 노드 1개, 전화 일치, 리뷰 마크업 금지, 금지 표현
- 링크: 내부 링크·앵커 존재, `target=_blank` 의 noopener·noreferrer
- 이미지: alt, width/height
- 매장 사실: 본문에 전화·주소·영업시간이 SSOT 값으로 있는지, 다른 전화번호 노출 금지
- 브랜드: 대표 브랜드 2개 이상 나열한 블록에 "등/다수/여러" (영문·한글 표기는 한 쌍으로 셈, "등입니다/등을" 같은 조사형 인정, "등록" 오인 제외)
- sitemap ↔ 색인 페이지 일치, robots에 `Disallow: /` 금지, llms.txt·rss 존재·금지 표현
- 가이드 마크다운의 매장 사실 리터럴(전화·주소·"도보 약"·"N년 개업") 금지
- 검색엔진 소유확인 파일(`naver….html`, `google….html`)은 페이지 검사 제외

**음성 테스트**: 규칙을 추가할 때마다 `dist/` 사본에 위반을 넣어 실패하는지 확인한다. 작업 트리를 `git stash`/`git checkout` 으로 되돌리며 테스트하지 않는다(커밋 전 수정이 사라진 사고가 있었다).

**화면**: 320·390px 모바일과 데스크톱 캡처, 주요 페이지 `scrollWidth == 뷰포트 폭`.

**독립 리뷰**: 만든 사람이 아닌 리뷰어(서브에이전트)가 읽기 전용으로 점검한다. 대상이 많으면 6파일 단위로 나누고, 보안 점검을 병렬로 돌린다. 판정·심각도·파일:줄·수정안을 받는다.
- 1차: 미확인 사실 단정(누진·근시관리·콘택트렌즈·창업자·같은 자리), 실명 바이라인, FAQPage 중복 → 수정
- 2차(재확인): 표현만 바뀐 채 같은 미확인 사실을 함의하는 문장 4곳 → 수정
- 3차(공개 후): 사진 촬영연도 미표기, 옛 간판 사진에 "이 간판을 찾아오세요", 의미 중복 FAQ, 가이드 매장 리터럴 재발, 조사 오류 → 전부 수정 + 감사 규칙 추가
- 보안: 외부 폰트 자체 호스팅, 배포 권한 job 분리, iframe referrer 정책, 액션 커밋 SHA 고정, noreferrer

## 6. 사진

- 쓸 수 있는 것: 운영자가 올린 네이버 플레이스 업체 사진(`business_N`), 운영자 본인 블로그 사진(사용 승인 후).
- 쓰지 않는 것: 손님 리뷰 사진(`placeReview_N`)·손님 블로그 사진(올린 사람 저작권, 운영자 허락으로는 부족), 네이버 거리뷰(네이버 저작권).
- 블로그 이미지는 본문 안 이미지만(URL 경로에 `.<블로그ID>/`), `type=w966` 으로 받아 번호 붙은 접사표를 만들어 **직접 보고** 고른다. 지도 캡처·배너는 뺀다.
- `photos.ts` 에 key·alt(눈으로 본 그대로: 색·간판 글자)·캡션·촬영연도·그룹을 적고, `PhotoGrid` 하나로 렌더링. `/gallery/` + 홈·소개·브랜드·오시는 길에 2~3장씩 섞는다.
- 촬영연도를 모든 노출 위치에 표기. 간판이 바뀌었을 수 있는 옛 사진에 길찾기 문구를 붙이지 않는다.
- 블로그 태그에 다른 업체 흔적이 있으면 운영자에게 한 번 확인한다.

## 7. 공개 (사이트 품질 승인 후)

순서: GA4·GTM → GitHub 저장소·Pages → 도메인 DNS → HTTPS. 브라우저 작업은 사용자 브라우저(Aside)에서, **사용자가 지정한 계정**으로만 한다(여러 구글 계정이 로그인돼 있어 기본 계정이 다른 경우가 많다).

1. **GA4·GTM**: GA4 속성(시간대 한국·KRW·이벤트 보관 14개월, 웹 스트림) → GTM 컨테이너에 Google 태그(측정 ID, Initialization - All Pages) → 게시. 사이트에는 GTM ID만 넣는다(gtag 중복 금지). 검증: `gtm.js?id=GTM-…` 에 측정 ID·버전 포함, 로컬 페이지 `window.google_tag_manager` 에 두 ID.
2. **GitHub**: `pages.yml`(main 푸시 → npm ci → build → audit → Pages 배포, 배포 job만 쓰기 권한, 취소 없이 순서 유지) + `check.yml`(PR: build·audit·390px 넘침·결과물 업로드). 모든 액션 커밋 SHA 고정. `.nvmrc`, README.
3. **도메인(Cloudflare)**: `astro.config.mjs` 의 `SITE_URL` 한 줄 교체 + `public/CNAME`. DNS는 전부 DNS only(회색 구름): apex A 185.199.108~111.153, AAAA 2606:50c0:8000~8003::153, `www` CNAME → `<계정>.github.io`, GitHub 도메인 인증 TXT.
4. **Pages 커스텀 도메인**: 워크플로 배포에서는 `CNAME` 파일이 무시되므로 API로 등록해야 한다(등록 전에는 도메인이 404). 인증서 `approved` 후 HTTPS 강제.
5. **검증**: http·www·github.io 주소가 모두 `https://<도메인>/` 으로 301, 주요 페이지·llms·robots·sitemap·RSS·CSS 200, 없는 주소 404, canonical·GTM 존재.
   - 공개 직후 "보안 연결 아님" 경고는 대개 HTTPS 강제 전 열어 둔 탭·캐시다. 혼합 콘텐츠가 없는지 확인 후 새로고침 안내. Cloudflare 프록시를 켜서 해결하려 하지 않는다(인증서 갱신이 깨짐).

## 8. 검색엔진 등록

병렬로 진행하고, 사람이 꼭 해야 하는 단계(CAPTCHA·PIN)는 **입력창 직전까지 준비해 둔 뒤** 그 한 단계만 넘긴다.

| 엔진 | 소유확인 | 제출 | 사람이 할 일 |
|---|---|---|---|
| 구글 서치콘솔 | 도메인 속성, DNS TXT | sitemap-index·sitemap-0, 핵심 3페이지 색인 요청 | – |
| Bing | 서치콘솔 가져오기 | sitemap·RSS, 홈 URL | – |
| IndexNow (Bing·네이버·Yandex) | `public/<32자 키>.txt` | 사이트맵 URL 전송, 배포마다 새 페이지 재전송 | – |
| 네이버 서치어드바이저 | HTML 파일 + 메타 태그 둘 다 배포 | 사이트맵(경로만 입력), RSS, 웹 페이지 수집(전체 URL 입력) | 소유확인·RSS 제출의 CAPTCHA |
| 다음 웹마스터도구 | robots.txt 인증 문구 | 사이트맵·RSS Seed, 홈 수집요청 | PIN 직접 설정·입력 |

- 네이버 웹 페이지 수집은 CAPTCHA 없이 가능하지만 `https://` 전체 주소만 받는다.
- 다음 PIN은 운영자가 직접 정해야 한다(에이전트가 정하면 아무도 몰라 인증이 막힌다). PIN을 재발급하면 robots.txt 문구가 바뀌므로 다시 배포한다. 문서 수집요청은 몇 건 뒤 조용히 제한된다 — 사이트맵·RSS를 먼저.
- PIN·계정 메모는 공개 저장소에 올리지 않고 `.gitignore` 된 `.local/credentials.md`(권한 600)에 둔다.

## 9. 운영

- 매장 정보 변경: `store.ts` 수정 → 푸시(자동 빌드·감사·배포) → IndexNow 재전송.
- 리뷰 수치: 네이버 플레이스 값과 기준일(`reviews.asOf`)을 함께 갱신.
- 가이드 추가: `src/content/guide/<slug>.md` → 목록·sitemap·RSS·llms.txt 자동 반영.
- 네이버 스마트플레이스의 영업시간·소개글·편의시설을 사이트와 같은 값으로 채운다(플레이스가 비어 있으면 지역 검색에서 손해).
- 며칠~몇 주 뒤 서치콘솔·서치어드바이저에서 색인 수 확인.
- 새 매장 사진이 생기면 `photos.ts` 에 추가하고 옛 사진을 교체.
